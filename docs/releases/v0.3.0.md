## What's new since v0.0.1

**Read saved runs in your own Python analysis.** The public, read-only `load_run(path)` function accepts a `run_NNN` directory or its `trials.tsv` and returns named NumPy trial arrays plus the original manifest and column dictionary:

```python
from psychophysics_lab.data.reader import load_run

run = load_run(r"C:\path\to\run_001")
contrast = run["trials"]["presented_display_contrast"].astype(float)
accuracy = run["trials"]["correct"].astype(int)
```

The existing TUI **Learn / Help** page links to the copy-and-paste [analysis guide](../ANALYSING_RUN_DATA.md).

**Reader compatibility.** The reader uses saved **column names**, not positions, and can inspect earlier unversioned tables or additional experiment-specific columns in a supported schema. It refuses unknown future numbered trial schemas instead of guessing their scientific meaning.

**Recording remains unchanged.** New runs still use the established 20-column, trial-schema-1 `trials.tsv`; the acquisition writer, adaptive rules, stimulus rendering, contrast definitions, calibration checks and canonical recording format were **not** changed by the reader feature. Future optional acquisition columns require a separate reviewed writer/schema update.

**Version alignment.** The Python distribution/package version is now `0.3.0`, matching the proposed GitHub release tag `v0.3.0`. The earlier historical GitHub `v0.0.1` snapshot remains available and retains its original internal package version `0.2.2`.

## Requirements and installation

- **Windows + Python 3.11** is the project's current laboratory workflow focus. Python `>=3.11,<3.12` is declared in `pyproject.toml`.
- Download the source archive of **this release** and extract it to a **new, empty folder**. Do **not** overwrite an existing Git checkout or private scientific edits with a ZIP. Run `run_psycolab.bat` to set up and launch PsyCoLab.
- Each laboratory maintains its own external acquisition-data directory, monitor/calibration records and experiment presets. Downloading an archive does not reproduce or certify the laboratory's physical screen, timing, photometer or GPU setup.
- Researchers updating a Git checkout should follow [safe updates](../SAFE_UPDATES_AND_LOCAL_WORK.md), not overlay source ZIP archives on old code.

## Validation and limitations

- The user reported **25/25 passing focused public reader and run-integrity tests** on Windows using Python 3.11 with a writable pytest temporary directory (24 October 2026). The one warning concerned a *different*, locally changed `new_probe_vertical_line_stimulus` source needing its own readiness retest.
- Those focused results are **not** a claim that the full repository suite passed, that earlier reported full-suite failures are resolved, or that physical acquisition is qualified. Re-run the focused tests against the **tagged** commit and retain the output before publishing.
- Independent loading of lab-owned external experiment Python is **not implemented**. For changes to scientific source, retain a private feature branch/fork; use local TUI presets for ordinary parameter changes.
- No software license has yet been selected in the repository. Public downloadability alone does not constitute an open-source license; repository/institutional review is still needed before promising redistribution rights.

For detailed results and scientific meanings of recorded fields, see the [trial data dictionary](../TRIAL_DATA_DICTIONARY.md), [schema policy](../SCHEMA_COMPATIBILITY.md) and [release policy](../RELEASE_POLICY.md).
