# PsyCoLab v0.4.0 — Windows 11 software baseline

**Release candidate.** The proposed release is a complete source checkout or
GitHub **Source code (zip)** or **Source code (tar.gz)** archive for Windows 11
x64. Use the approved conda-forge CPython 3.11.15 profile and its hash-locked
dependencies. Download the interpreter separately. The source archive needs
its own editable installation. The Python wheel and sdist are packaging
verification artifacts, and the proposed distribution includes no installer,
interpreter or dependency bundle.

## Scientific scope

The ten official studies put experimental choices, scientific methods and
framework integration in a readable A1/A2/B Python protocol. Each declares its
stimulus slots and trial events. Shared stimulus classes handle rendering,
including separate components for the ellipse and line studies. This model
includes scientific-source changes accumulated since v0.3.0. The v0.4.0
versioning changes add no experiment, equation, stimulus, timing rule, adaptive
rule, estimator or acquisition-format change to the verified integrated
baseline.

| Official experiment IDs | Scientific boundary |
| --- | --- |
| `contrast_sensitivity`, `contrast_sensitivity_windowed` | Gaussian and circular-windowed grating protocols have distinct envelopes and IDs. Keep the selected aperture, digital modulation definition and provenance when comparing results. |
| `ellipse_centre`, `ellipse_major_axis` | Separate ellipse and probe components. Use each protocol's recorded geometry, contrast convention, trial order and condition labels. |
| `line_position_baseline`, `line_position_flanker` | Distinct baseline and flanker protocols. Retain the selected probe placement and inducing stimulus settings. |
| `orientation_task`, `orientation_adaptive` | Preserve each study's angle, strength, response and analysis conventions. |
| `probe_above_below` | Spatial position judgments relative to fixation, with the recorded response mapping. |
| `example_experiment` | A readable teaching protocol for exercising the same execution and recording path. |

All ten provide adaptive and constant-stimuli methods. Fixed schedules report
observed responses. A psychometric fit or threshold needs a justified
analysis. Compare studies and historical results using the exact protocol,
units, configuration, calibration and saved provenance. Digital stimulus
commands alone do not establish physical luminance or contrast.

## Researcher workflow and infrastructure

- Open Configure and Review to inspect effective values, units and controlling
  inputs. Edit scientific settings, including supported stimulus geometry, in
  the existing controls and save locally in JSON. Use Preview, Test or
  simulation before acquisition. Trusted external laboratory experiments and
  stimuli use the same generic interface and their own Test → Ready workflow.
- Save configurations from Review and export portable schema 2 JSON. Import
  previews changes and checks scientific source, engine and dependency
  identity before applying them. Imports retain lineage where applicable.
- **Save new preset** refuses an occupied filename, including Windows
  case-only collisions. **Update selected preset** retains its backup history.
- Start with `PsyCoLab.bat` for launch, Check / Repair or Python Workspace.
  Set up the approved environment as described in the Windows guide. The
  launcher verifies it on repeat startup. Retarget shortcuts that point to a
  retired batch wrapper. The README and launcher share the original PsyCoLab
  text wordmark.
- The software is BSD-3-Clause. Cite Alexander A. Minns and report the exact
  source revision used. The acknowledgements credit AI-assisted implementation
  and `@feizhanxia` for the Windows setup contribution.

## Compatibility and safe updates from v0.3.0

1. Keep the old source and environment at their existing paths. Back up the
   old configuration, calibration, external laboratory source and research
   records. Put v0.4.0 in a new folder with a fresh approved environment.
   Set distinct configuration and data roots explicitly. Sibling checkouts
   can otherwise share their defaults.
2. Validate on disposable copies. Open supported local JSON and presets and
   review the effective values. Read supported historical runs with
   `load_run(path)`. The canonical writer retains the established 20-column
   trial schema 1. Keep raw trials, manifests, dictionaries and saved analyses.
   Revalidate affected extension source and dependencies before marking
   them Ready. Keep local apparatus measurements with their original setup.
3. The published v0.3.0 pre-release predates portable import. For a schema 1
   portable file, open the verified original settings and export a fresh
   schema 2 file. Schema 2 imports require matching scientific fingerprints
   and dependency versions. Exports from before the preset safety fix may
   require regeneration because their engine fingerprints differ. A version
   label difference alone can be accepted with a warning when identities
   match. Ordinary local experiment and stimulus JSON use separate formats.
4. To roll back, close the new release and reopen the retained old launcher
   with its own checkout, environment and roots. Keep the new outputs
   separate. Use a matching reader for files the earlier release does not
   support. Check / Repair services the selected installation. It does not
   switch versions or perform an in-place upgrade.

## Acceptance before publication

[Issue #82](https://github.com/aminns123/Psychophysics_Collaborative_Lab/issues/82)
tracks independent Windows 11 acceptance and release approval. Same-host
software verification and CI support the candidate. The maintainer still
needs independent Stage 4/5 observations and an evidence-based disposition
of [the reported collaborator native-run failure #123](https://github.com/aminns123/Psychophysics_Collaborative_Lab/issues/123).
The cause and impact of that report remain unresolved.

Every laboratory must qualify its own display geometry, photometry, output
precision, stimulus and response timing, audio where applicable, and
protocol. Sharing settings and passing software tests establish neither
optical equivalence nor physical qualification.

### Independent Windows 11 checklist

1. On a separate Windows 11 x64 workstation, record the exact approved
   source SHA and interpreter profile. Extract the full source archive into
   a fresh path containing spaces and provision the approved environment
   separately. Use disposable configuration, data and extension roots.
2. Run the native launcher check, launch from the menu, exit and relaunch.
   Verify mouse and keyboard input, Python Workspace, and unchanged
   setup-record hash on reuse. Exercise the documented recovery route in a
   separate disposable installation and record the outcome.
3. Configure one official experiment, edit an input in Review, Preview, Test
   on the connected display if preflight permits, and simulate twice. Reopen
   the saved outputs. Check schema 2 save, import preview and cancellation.
   Verify a copied trusted laboratory extension through Test → Ready.
4. Keep v0.3.0 intact. Open a copied old preset and relocated synthetic run
   in v0.4.0. Save a new synthetic result in its own root. Reopen the
   retained v0.3.0 installation and old run. Compare protected file and setup
   hashes. Record unsupported formats or workflow failures.
5. Record operator, machine, SHAs, paths, actual observations, results and
   redacted evidence. Keep physical qualification and software sign-off
   separate. Obtain maintainer approval for the final source and release scope.
